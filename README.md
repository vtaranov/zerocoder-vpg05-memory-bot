# VPg05. Диалоговый Telegram-бот с памятью

Учебный проект на Python 3.13: pyTelegramBotAPI, OpenAI и Pinecone. Бот сохраняет исходные сообщения пользователя, находит подходящие воспоминания и использует их в ответе. Ответы бота в векторную память не записываются.

## Установка

```bash
git clone https://github.com/vtaranov/zerocoder-vpg05-memory-bot.git
cd zerocoder-vpg05-memory-bot
python3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
cp .env.example .env
```

Заполните ключи, имя существующего индекса Pinecone, токен Telegram и свой числовой Telegram ID в `ALLOWED_USER_IDS`. Несколько разрешённых ID разделяются запятыми. Бот обрабатывает только личные сообщения разрешённых пользователей.

Нужен готовый индекс Pinecone размерности 1536 с метрикой cosine. Индекс автоматически не создаётся и не удаляется. Каждому сочетанию пользователя и чата соответствует отдельный namespace с префиксом `vpg05-memory-`. Данные других учебных проектов не используются.

`OPENAI_BASE_URL` поддерживается и для эмбеддингов, и для Responses API. Если адрес пуст, SDK использует стандартный адрес OpenAI. При указании другого провайдера он должен поддерживать embeddings, Responses API, выбранную модель и Structured Outputs. Автоматической замены модели или API нет.

## Запуск

```bash
.venv/bin/python pinecone_manager.py
.venv/bin/python bot.py
```

Первая команда выполняет реальную проверку индекса и поиска. Вторая запускает Telegram-бота. Остановка - Ctrl+C. Не запускайте другие приложения с тем же Telegram-токеном. Активный webhook останавливает запуск; приложение не отключает его автоматически. При запуске пропускается старая очередь сообщений, поэтому тестовые сообщения отправляйте после строки `bot_ready`.

Команды бота:

- `/status` - модель и порог.
- `/memories` - исходные сообщения в памяти.
- `/reset` - инструкция очистки.
- `/reset confirm` - удалить память текущего пользователя в текущем чате.
- `/help` - справка.

Обычный текст обрабатывается как сообщение диалога и кандидат для сохранения.

## Проверка перед записью

1. `text-embedding-3-small` создаёт вектор сообщения.
2. Pinecone возвращает одну ближайшую запись в namespace пользователя.
3. Если записей нет или cosine ниже `SIMILARITY_THRESHOLD`, создаётся новая запись: `inserted`.
4. При высоком сходстве точное совпадение текста сразу даёт `skipped`.
5. В остальных случаях модель возвращает структурированное решение:
   - `duplicate`: перефразирование без новых фактов - `skipped`;
   - `revision`: исправление одного того же факта без потери других сведений - `updated`, ID сохраняется;
   - `different`: другой факт, субъект, вопрос или неоднозначность - `inserted`.

Порог по умолчанию 0.75 настраивается в `.env`. Это порог поиска кандидата, а не вероятность совпадения смысла. Дополнительная проверка моделью - осознанное расширение примера урока: «хочу на Марс» и «не хочу на Марс» нельзя считать одинаковыми предпочтениями. Если модель или API проверки не ответили, существующая запись не перезаписывается.

После записи проверяется её видимость через fetch и поиск. При таймауте приложение честно сообщает, что операция могла уже сохраниться. Обработка сообщений последовательная в одном процессе; распределённая транзакционная защита от одновременных записей нескольких приложений не реализована.

## Формирование ответа

После обработки памяти бот ищет до пяти близких сообщений и передаёт их модели вместе с текущим запросом. Сохранённые сообщения помечены как данные, а не системные инструкции. История ответов ассистента не сохраняется и не передаётся между запросами. Поэтому это память по смыслу, а не полная последовательная история беседы.

Память содержит только `user_message`, ID записи, время создания/обновления и доступные имя, фамилию, username. Отсутствующие поля Telegram пропускаются; `None`, `bot_response` и произвольные поля не записываются. Вопросы и приветствия тоже могут сохраняться: классификатор важности фактов в этом ДЗ не реализован.

Если сохранение состоялось, но генерация ответа не удалась, бот сообщает об этом отдельно. Команда `/memories` позволяет проверить фактическое состояние.

## Проверки

```bash
.venv/bin/python -m unittest -v
.venv/bin/python -m pip check
.venv/bin/python verify_live.py
```

Автономные тесты заменяют внешние API. `verify_live.py` делает реальные платные/квотируемые запросы к OpenAI и Pinecone в уникальных тестовых namespace VPg05. Проверяет вставку, перефразирование, точный повтор, отрицание, новую тему, отсутствие имени, изоляцию пользователей, восстановление после нового подключения и очистку своего пространства. При успешном завершении удаляет только записи этих тестовых namespace. При неудаче сохраняет протокол с типом ошибки для диагностики.

Протоколы находятся локально в `evidence/`. Лог бота `evidence/bot.log` содержит действия, ID и оценки сходства, без исходных сообщений и ключей. Краткие проверенные результаты - в [VALIDATION.md](VALIDATION.md).

## Ограничения

Семантическое решение модели может ошибаться. Найденный один ближайший кандидат не гарантирует обнаружение всех дублей; слишком высокий порог пропустит часть перефразирований. При обновлении сохраняется последняя исходная формулировка, история версий не ведётся. Проверка на нескольких фразах подтверждает работу демонстрации, но не измеряет качество на произвольных диалогах.

Сообщения передаются в OpenAI для эмбеддингов, проверки и ответа, а затем сохраняются в Pinecone. Responses API вызывается с `store=False`. Это не отменяет хранение самой памяти в Pinecone. Для демонстрации используйте вымышленные сведения.

Проект рассчитан на macOS/Linux (`fcntl` для блокировки второго экземпляра). Ключи, окружение, журналы и рабочие данные исключены из Git. README самодостаточен, предыдущие учебные проекты для запуска не нужны.
